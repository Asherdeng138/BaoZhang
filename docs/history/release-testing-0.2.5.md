# Windows 0.2.5：独立发票预览窗口

人工核对时，点击右侧发票图片或“查看大图”，打开独立的系统窗口。该窗口不是主界面的模态对话框，可以边看大图边在主窗口填写金额、日期、商家和备注。支持移动窗口、放大、缩小、左右旋转、适合窗口、PDF 翻页、关闭按钮和 Esc。关闭预览不会清空未保存的填写内容；旋转仅影响查看，不修改原件。

预览窗口只获得读取当前预览原件和关闭自身的接口，不获得主窗口的保存、删除、导出等接口。主进程检查请求窗口身份及本地页面来源，并阻止外部导航和另开网页。

0.2.5 保留 [0.2.4 的 OCR 修复与金额候选](release-testing-0.2.4.md)，包括每次便携启动使用独立临时目录、引擎启动失败时暂停批次、图片首次未取得金额时尝试旋转临时图识别。永久票据目录不变。先保存当前填写内容并关闭旧版，再运行新版；失败票据可重新勾选识别，不必重新导入。

## 最终产物验证

- 源码及打包后的 Electron 预览测试通过：独立系统窗口、主表单同时编辑、预览接口权限、图片点击打开、缩放、旋转像素位置、适合窗口、关闭和 Esc、未保存字段、原件字节保持、PDF 翻页。
- 最终 0.2.5 单文件 EXE 实际打开大图后，在主窗口填写金额，再旋转、缩放和关闭预览，字段保持。真实金额候选点选和保存通过。
- 最终 EXE 重复启动测试通过：后启动副本退出后，原窗口的 OCR 文件仍在，真实 OCR 仍可执行。
- 原来 22 张失败图片的副本全部完成识别；21 张取得金额，18 张取得日期，22 张取得商家候选。候选是否正确仍需人工核对，未取得的字段仍需填写。
- 11 项服务测试、界面金额候选和额度回归、引擎失败暂停及重试通过；最终打包程序连续多图拖入、真实 OCR、编辑、PDF/Excel 导出、归档回收站和重启持久化回归通过。
- 源码与完整 ZIP 内运行文件一致，ZIP CRC 校验通过；测试报告记录最终 EXE/ZIP 的 SHA-256。最终 EXE 和 ZIP 经本机 Defender 扫描未发现威胁，尚未使用受信任 Authenticode 签名。

测试使用独立数据目录和原件副本，排查前 37 张记录的编号及原件哈希保持。测试未向原账本写入数据。具体结果见交付目录的 `0.2.5-test-report.json` 和 `Windows-0.2.5-测试说明.md`。Android 本次未改动，仍为 0.1.3。
