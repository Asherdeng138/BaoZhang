# 归档与回收站实现及验证

2026-10-10，用户确认的规则：归档只增加标记，发票仍在日常列表和导出列表显示；仅归档页的删除进入回收站，其他删除入口保持永久删除。

## 当前行为

- Windows 的两个导出文件写入成功后询问是否归档。Android 的两个文件成功生成后，在文件结果页询问是否归档，保存到文件夹与分享按钮仍保留。备份 ZIP 不询问归档。
- 使用本次成功导出的 ID 集合，而不是之后变化的勾选集合。取消或失败的导出不归档。
- 已归档发票保留原件和日常可见性，仍参与出差餐补额度统计，可再次导出，也可取消归档。
- 归档页删除保留归档时间和删除时间；删除时间不会因重复点击、重启或 Windows 备份恢复重新计时。
- 回收站记录不参与日常列表、正常导出或餐补额度统计；30 × 24 小时以内恢复到归档区。
- 启动以及运行期间约每分钟检查到期记录。应用关闭时不执行清理，到期记录在下次运行时清理。原件仍被其他记录引用时保留该文件；清理失败可重试。独立导出文件与外部备份不在清理范围内。
- Android SQLite v1 → v2 仅增加 `archivedAt`、`deletedAt` 两个列，默认值为 0，不删除旧表或旧记录。Windows 旧 JSON 不含这两个字段时按未归档、未删除处理；备份恢复保留有效生命周期时间，并跳过已经到期的回收站记录。
