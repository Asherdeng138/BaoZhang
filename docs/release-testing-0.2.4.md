# Windows 0.2.4：OCR 启动失败与金额候选

## 原因与修复

本地错误记录中的 22 张图片均报 `Cannot find module 'tesseract.js/src/worker-script/node/index.js'`。原件读取成功，失败发生在识别引擎启动前。0.2.3 包内存在这一文件，独立启动时可以识别；但两个同版本便携副本复用固定临时目录。后启动副本因单实例锁退出时，便携启动器会删除这一目录，先启动的应用仍在运行，却无法再加载 OCR 文件。隔离重复启动已复现相同错误。

0.2.4 使用每次启动独立的临时解包目录。应用的永久票据数据目录不变；只修改运行文件的临时目录，不迁移、不删除票据。用户应先关闭旧报账窗口，再打开新版，重新勾选失败票据并识别，无需删除或重新导入原件。

打包工具固定为 electron-builder 26.0.12。该版本 `NsisTarget.js` 的实现是 `typeof unpackDirName === "string" || !unpackDirName` 时设置固定目录，与类型注释所述 false 行为不一致。因此当前设置 true，使 `UNPACK_DIR_NAME` 不被定义，使用 NSIS 为每个进程创建的 `$PLUGINSDIR/app`。升级打包工具时必须重新运行最终便携 EXE 的重复启动测试，以产物行为为准。

OCR 首次启动前检查本地工作程序和两种语言模型。无法启动时显示明确提示，并暂停本批其余识别，保留未处理的原件和记录；不再把整批票据连续标记成同一引擎错误。恢复后可重新勾选重试。

## 金额候选

金额字段下面显示从原始识别文字提取的候选按钮，与安卓版共用解析规则。可点选填写或手动输入。更改候选会取消当前核对勾选、更新预计额度，不会自动确认或覆盖原件。候选仍须对照小票实际付款金额核对；解析会排除税额、小计、找零及折扣等明确标记的金额。

## 横向小票与人工核对预览

图片第一次识别没有提取到金额时，再尝试旋转临时图片 90°、270°、180°。只有带明确实付总额的结果才替代第一次结果，优先同时具有有效日期的结果；识别到弱金额时不会随意用其他方向覆盖。找到可靠的总额和日期后停止后续方向尝试，正常识别到金额的图片保持一次识别。原始附件字节不变，候选仍需核对。

人工核对时点击右侧发票图片或“查看大图”，打开独立预览弹窗。支持放大、缩小、左转、右转、适合窗口、右上角关闭和 Esc 返回；PDF 支持上一页/下一页。关闭弹窗不重新创建核对表单，未保存的日期、金额、商家和备注保留。旋转与缩放只影响查看，不修改附件或已导出的文件。

## 验证方法

- `desktop/tests/ocr-failure.test.cjs`：模拟引擎无法启动，确认第一张后暂停、保留剩余记录、显示提示且可以重试。
- `desktop/tests/ui.test.cjs`：多个金额候选的点选、排除税额与折扣、重新核对要求，以及现有日期、商家和额度回归。
- `desktop/tests/viewer.test.cjs`：实际 Electron 图片点击预览、缩放、旋转像素位置、适合窗口、关闭/Esc、未保存字段及原始字节保持、PDF 翻页和加载中关闭。
- `work/release-build/portable-ocr-test.cjs`：对最终 EXE 实际解包并调用真实 OCR；`collision` 模式重复启动同一 EXE，确认原进程文件仍在且可以识别；`originals` 模式在独立测试数据中导入原来 22 张失败图片的副本，执行真实批量识别并校验原件哈希。
- 11 项存储/导出测试及打包程序多图导入、真实 OCR、核对保存、导出与归档回收站回归。

原账本和原件通过本地备份校验，不在这些测试中写入。测试识别成功只表示程序能执行并输出候选，不代表金额、日期或商家无需人工核对。最终结果以随交付安装包提供的 `0.2.4-test-report.json` 为准。
