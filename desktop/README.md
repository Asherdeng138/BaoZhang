# 随手报账 · 电脑版

基于手机版 HTML 界面扩展的 Windows 桌面应用，金额固定为英镑。程序内置离线英文和简体中文 OCR，不上传票据。

## 使用
1. 保存当前填写内容，关闭旧电脑版，双击 BaoZhang-Desktop-0.2.5.exe。沿用原本的本机数据目录。
2. 可从微信连续拖入多张票据，待导入列表持续追加并显示总数量；可移除单张或清空，再选择种类一起导入。也可一次拖多个文件或点击“批量添加发票”多选文件。微信图片可复制后点击“粘贴微信图片”。
3. 工作台勾选发票，点击“识别选中”。结果为待核对状态。
4. 对照右侧原件修改日期、英镑金额、商家、所在地、分类和备注。点击发票图片或“查看大图”打开独立系统窗口，可同时在主窗口填写金额、日期和备注；预览支持放大、缩小、左右旋转、PDF 翻页和关闭，未保存的核对内容保留。识别后金额字段下方有候选按钮，点击填写，也可手动输入。点选后须重新勾选核对，再保存并查看下一张。
5. 在“报账导出”中先选费用种类，再选日期和发票，生成合并 PDF + Excel。
6. 通过日历标记出差、办公、休假；颜色同时配有文字。点击日期查看发票。

## 当前功能
- 除市内交通按月份命名外，PDF/Excel 文件名使用导出界面选择的起止日期及费用种类。例如：`2026-10-01至2026-10-31_出差餐补报账_发票合集.pdf` 和 `2026-10-01至2026-10-31_出差餐补报账_明细汇总.xlsx`。每次导出使用独立文件夹，重复导出不会覆盖之前的文件。
- 选择“出差餐补”时，商家字段旁显示 Tesco、麦当劳、Sainsbury's、ASDA、Costco 快捷按钮；识别为空或清空商家后仍可点选，也可输入其他商家。按钮只填写当前商家，保存后保留；更改快捷商家会取消当前表单的核对勾选。
- 识别后的规则提取增加常见商家匹配，排除总优惠/总税额，并对强总额字段中的部分易混字符和小数空格给出候选修正及警告。仍须人工核对，尚未以真实票据测量准确率提升。
- 日期提取支持带空格、两位年份、`9th Oct. 2026`、`Sept`、全角数字等写法，并对日期串内的 O/0、I/1 作带警告修正。核对页面提供日期候选按钮；到期日不自动填入费用日期，多个同样可信的日期需点选。已有人工日期不会被 OCR 覆盖，缺少年份时不会补上今年。
- 日历右侧直接选择出差、办公、休假或清除，并提供批量标记。连续出差餐补总额度 = 连续出差天数 × £50，只统计已确认餐补；单日可超 £50，但整段超额时提醒。办公/休假/未标记日断开连续出差，跨月或跨年不截断。
- 日历显示整段已确认餐补、额度、剩余或超额；编辑时显示本张确认后的预计合计；导出时核对关联整段全部已确认餐补，不只核对所选日期/发票。超额仍可保存和导出，其他费用不受影响；未标记出差的票据提示额度尚未计算。
- 低于额度时始终明确提醒未使用金额，不设余额阈值。例如额度 £250、已用 £240，提示还有 £10.00 未使用；日历、编辑、导出和确认保存后都会提示。额度相等显示已用满，不自动补录或增加金额。
- 这些改动属于当前源码，前述下载链接中的旧 EXE 不包含本次更新。本地 OCR 引擎选型见 [本地 OCR 方案](../docs/local-ocr-options.md)。

## 支持范围
- Windows 10/11 64 位。无需另装 Node.js、Python 或 OCR。
- JPG、JPEG、PNG、WebP、PDF；每批最多 100 个文件，单文件最多 50 MB。
- 一个文件对应一张发票；同一 PDF 的多页放在一条记录中。
- PDF 识别前 3 页，导出所有页面。可选择具体发票导出，尚未核对的票据不参与导出。
- 相同文件内容重复导入会跳过。OCR 不覆盖已有人工填写的非空字段。
- 加密、损坏或不支持的附件可能无法识别/导出；识别失败仍可保留原件并手工填写。
- 出差餐补可按票据记录；当前没有单独的无票补贴计算规则。
- 识别不能保证准确，金额和日期必须核对；所在地需人工填写。
- 原 PDF 合并保留页面内容；数字签名在合并后的新文档中不再有效，原 PDF 仍保留。
- 每次导出最多 300 页。备份的原件和信息合计最多 250 MB。
- 左下角可备份、恢复电脑版 ZIP。恢复采用合并并跳过重复原件；安卓备份暂不支持直接导入。
- 数据在 Windows 用户的应用数据目录下，关闭/重新打开保留。移动 EXE 不影响同一 Windows 账户的数据。

## 开发与打包
Node.js 22: `npm install` → `npm run build` → `npm test` → `npm run smoke` → `npm run dist`。
前端构建后可运行 `npm run test:ui`，验证餐补商家、手工编辑及导出文件名显示；此项使用模拟 Desktop 接口，不代替服务测试、Electron/真实 OCR 测试或打包验收。
`npm install` 会从官方 tessdata_fast 仓库下载离线 OCR 模型。源码和 HTML 在本目录；HTML 通过 Electron 本地接口实现文件管理与 OCR，不是独立的浏览器演示页。


归档与回收站：PDF/Excel 成功生成后可选择为本次导出的发票增加归档标记；日常列表、再次导出和餐补累计仍包含归档发票。两端有“归档与回收站”入口，可取消归档。从归档区删除才进入回收站，其他删除入口保持永久删除。回收站保留删除时间，30 × 24 小时内可恢复到归档区；期限不因重启或恢复备份而重新开始。到期后在启动或运行期间（约每分钟检查）清理信息和没有被其他记录引用的本机原件；程序关闭时不会执行清理，已导出的文件及独立备份不受影响。安卓数据库从 v1 非破坏升级到 v2；旧记录默认未归档。回收站记录不参与日常列表、导出及餐补统计。


市内交通按每个自然月 £150 累计：已归档发票仍计入，待核对及回收站发票不计入。日历、编辑预览、确认保存及导出显示全月额度与超额提示；超额只提示，仍可保存和导出。部分日期或部分勾选不会按比例缩小月额度，也不会只统计选中发票。市内交通 PDF/Excel 文件名例：`2026年10月_市内交通报账_发票合集.pdf` / `_明细汇总.xlsx`；跨月使用 `2026年10月至11月`，跨年使用 `2026年12月至2027年1月`，月份根据导出界面选择的日期范围决定，文件名不写日。其他类别继续使用起止日期；Excel 内仍保留实际发票日期及所选导出范围。
